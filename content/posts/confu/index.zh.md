当前，随着计算机多核硬件的飞速发展，多线程并发程序越来越受到欢迎并被广泛使用。然而，由于共享内存空间访问的隐蔽性以及并发线程调度执行的随机性，多线程程序极易出现并发缺陷，且这些缺陷往往难以发现和复现。现有的并发缺陷检测方法各有其局限性：例如基于系统测试和符号执行的方法，由于存在状态空间爆炸问题，难以扩展至大规模并发程序；而基于概率调度的方法则缺陷命中率非常低。

为了应对并发程序测试在今天面临的巨大挑战，DATE团队开发了基于动态程序测试技术的多线程并发缺陷检测工具DATE-Confu，该工具面向JVM应用。该工具以待测JVM可执行程序（.class文件或.jar文件）为输入，输出为在待测程序中检测到的并发缺陷集合。目前，该工具能够检测包括数据竞争（data race）、死锁（deadlock）、空指针解引用（null pointer dereference）等在内的六类严重并发缺陷，用户可以按需选择检测哪些类型的并发缺陷。

DATE-Confu的关键创新在于将引导式调度模糊测试（guided schedule fuzzing）技术与符号轨迹分析（symbolic trace analysis）技术有效结合。下图展示了DATE-Confu的架构示意图。该工具利用模糊测试技术高效遍历多线程程序庞大的状态空间，同时借助符号轨迹分析技术快速发现程序中尚未探索的控制分支，从而为迭代模糊测试提供有效信息，使DATE-Confu更快达到更高的测试覆盖率。目前，DATE-Confu已在多个工业级项目上完成测试，实验结果表明该工具测试效率高，且能够发现隐藏更深的并发缺陷。

# 插桩

DATE-Confu工具使用ASM字节码插桩框架来实现其插桩功能。ASM是一个用于操作Java字节码文件的框架。一般来说，对普通Java文件的字节码操作流程包括以下3个步骤：

- 编译Java源代码获取Java字节码
- 使用ASM的ClassReader读取字节码，采用访问者模式对字节码进行修改，然后使用ClassWriter生成新的字节码
- 将新的字节码加载到JVM中执行

总体插桩过程分为两个部分。第一部分是DATE-Confu工具利用Java Agent模式对检测算法所在的Java字节码进行插桩。第二部分是在检测到被测模块的字节码需要被加载到JVM中运行时，再次调用Agent中的Transform方法以拦截被测模块的字节码。插桩完成后，将插桩后的字节码加载到JVM执行。此时，在JVM上运行的字节码会调用DATE-Confu中的检测算法进行缺陷检测。

![ASM](/posts/confu/images/ASM.jpg)
<div align="center">字节码插桩流程</div>

在插桩过程中，需要选择特定的字节码进行处理，以避免对Java中的通用模块进行插桩而产生不必要的输出。例如，JDK中包含的模块会在Agent的Transform方法中被排除。通常，插桩的目标是被测字节码以及该字节码所依赖的其他包中的字节码。因此，需要确保与被测字节码紧密相关的包中的字节码能够在运行时被类路径（classpath）找到，或者使用排除指定类的命令行参数来避免对指定类进行插桩。

# 线程调度

对于多线程程序而言，模糊测试的本质是在线程调度中引入随机性。当前常见的做法是在底层操作系统之上构造一个高层调度器，该调度器通过强制执行上下文切换来控制调度。通常，上下文切换是通过引入`sleep()`、优先级变更等操作来实现。

在DATE-Confu工具中，我们使用优先级变更操作来实现低开销的上下文切换，同时避免引入死锁。为了生成多样化的线程调度序列，现有技术大多在事件级别（event level）实现调度模糊测试，即在某特定事件之前或之后随机插入调度操作以实现上下文切换——例如，在多线程程序的每一次内存写入操作之前插入`sleep()`指令，可以使不同线程在执行内存写入时交错执行。然而，由于实际应用程序中存在大量事件，事件级别的模糊测试导致缺陷命中概率相对较低。

为了解决事件级别模糊测试缺陷命中概率低的问题，在开发DATE-Confu工具时，我们提出了内存访问组（Memory Access Group, MAG）技术来优化调度过程中的模糊测试。内存访问组技术的核心思想是将连续的内存访问划分为若干组，并对每个组内的调度进行模糊测试，这样可以有效缩小调度的状态空间，提高缺陷命中概率。然而，仅依靠内存访问组技术的优化尚不足以使我们更有效地生成触发缺陷的轨迹。为了使线程调度模块更高效地定位程序中的并发缺陷，我们提出了一种基于内存访问组技术的随机化模糊测试技术。该技术将模糊测试过程建模为搜索问题，并引入蒙特卡罗马尔可夫链（Monte Carlo Markov Chain, MCMC）方法来优化搜索过程，以获取最优搜索解。

# FastTrack算法

数据竞争最基本的检测算法为Happens-Before与Lockset检测算法。随着研究的不断深入，研究者们在这两个经典算法的基础上持续进行优化和改进，衍生出今天广泛使用的各类算法。DATE-Confu工具所使用的FastTrack算法是对Happens-Before算法的优化版本，用于高效检测数据竞争并发缺陷。Happens-Before算法的基本思想是记录每一次共享内存访问，并检查其与前一次访问之间是否存在Happens-Before关系——若不存在该关系，则报告数据竞争。FastTrack算法的基本思想与之类似，但引入了多项改进，有效提升了算法的时间复杂度和空间复杂度。

通过对大量程序的观察可以发现，在数据竞争检测操作中，线程同步操作相对于读写操作占比较小，读写操作占比高达96%。FastTrack算法高效的关键在于，99%的读写操作监控无需使用完整的`vector clock`向量时钟，而是采用了一种更轻量级的数据结构。FastTrack算法分别从数据竞争的三种情况进行讨论：写-写竞争、写-读竞争和读-写竞争。

# NPD检测算法

NPD（Null Pointer Dereference）检测算法是DATE-Confu中用于检测空指针引用的算法。空指针解引用缺陷可参考CWE 476中的详细描述。NPD检测算法依赖于两个关键技术：（1）并发偏序关系识别；（2）内存采样。算法流程总结如下：

1. 动态加载被测程序字节码
2. 对字节码进行插桩，根据不同的JVM字节码指令插入内存采样接口。例如，针对PUTFIELD指令，栈顶元素为`{value, objectref}`，分别表示要写入内存的值和对象引用，此时内存采样接口将捕获该`value`值并在算法中进行维护
3. 运行被测程序，产生运行时轨迹（runtime trace）
4. 动态识别Happens-Before关系，判定不同线程中的特定操作（如内存访问、加锁/解锁操作等）之间是否存在严格的并发偏序关系，即Happens-Before关系
5. 动态截获不满足Happens-Before关系的内存访问操作对($x_1$, $x_2$)，确保$x_1$和$x_2$中包含一次写入操作和一次读取操作
6. 在截获的内存操作对($x_1$, $x_2$)中检查对应的内存访问值是否为null；若为null，则说明在并发运行环境中，由于并发不确定性，可能出现空对象引用，从而导致程序崩溃

NPD算法可以看作对FastTrack算法的扩展和精化，用于自动在并发操作中定位可能引发的空指针解引用问题。如图所示，当一个程序被多线程并发访问时，NPD检测算法能自动捕获`(executor!=null, executor=null)`和`(executor.start(), executor=null)`这两对并发内存访问，并通过检查内存采样，判定`(executor.start(), executor=null)`这一对操作可能触发空指针解引用问题。

# GoodLock检测算法

在一个线程集合中，当每个线程都在等待集合中另一个线程所持有的互斥资源时，所形成的循环等待即为死锁。在所有并发缺陷中，死锁是较为常见的一类。一旦发生死锁，可能导致多线程程序的响应时间增加、吞吐量下降，甚至直接崩溃和宕机，严重威胁并发程序的可用性和可靠性。与大多数并发缺陷一样，死锁具有难以暴露、复现和调试的特点。

DATE-Confu工具检测死锁并发缺陷主要通过实现GoodLock算法。GoodLock算法能够检测被测并发程序在运行时是否可能发生死锁。该算法主要通过构建锁树（lock tree）来进行判断。现有的GoodLock算法能够处理任意数量线程之间的死锁问题。算法将各个线程的锁树连接形成锁图（lock graph），通过遍历所有可能路径来寻找有效环路，从而判定程序是否可能发生死锁。此外，GoodLock算法将运行时检测与静态分析（static analysis）相结合，在前人工作基础上实现了一种类型系统（type system），不仅可以检测Java程序中的死锁问题，还能提供更强的原子性保证。
