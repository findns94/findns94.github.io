一个 Lua 函数在 LuaJIT 内部经历五个阶段：字节码 → IR → 优化后的 IR → 机器码 → 执行。**IR（中间表示）**是连接它们的枢纽。录制器写 IR。优化器变换 IR。发射器读 IR。每个编译器阶段都说同一种语言。

这就是 IR 被称为 LuaJIT「世界语」的原因——这种共同语言让编译器的模块化设计成为可能。理解 IR 就是理解 LuaJIT 编译器的核心。

在本文中，你将学习 IRIns 结构、约 120 个操作码、类型系统、SSA 属性、引用系统，以及每个优化阶段如何在发射器将其转换为机器码之前变换 IR。

> **核心要点**
> - LuaJIT 的 IR 采用**严格 SSA 形式**：每个值只定义一次，支撑强大的优化。
> - IRIns 结构是一个 64 位联合体：操作数、类型、操作码，以及（分配后）寄存器/溢出信息。
> - 约 120 个操作码按类别组织：守卫、常量、算术、内存、分配、屏障、转换、调用。
> - 常量被驻留（去重）并从 REF_BIAS 向下增长；指令向上增长。
> - 每个优化阶段（FOLD、FWD、NARROW、DCE、LOOP、SPLIT、SINK）都在 IR 上运作——它就是通用语言。

## 什么是 SSA 以及为什么重要

**SSA（静态单赋值）**是中间表示的一种属性，其中每个变量只被赋值一次。在 LuaJIT 的 IR 中，这意味着每个值只有一个定义点，所有使用都通过 IR 引用指回该定义。

### SSA 与非 SSA 对比

```
 非 SSA（普通变量）：               SSA（LuaJIT IR）：

 x = 1                                [1] KINT 1
 x = x + 2      ← x 被重新赋值！        [2] ADD [1], KINT 2
 y = x * 3                            [3] MUL [2], KINT 3
 x = y - x      ← x 被重新赋值！        [4] SUB [3], [2]   ← 用的是 [2]，不是"x"
                                      [5] ADD [4], KINT 1
```

在非 SSA 代码中，`x` 被赋值两次。为了优化，编译器必须追踪哪个是哪个。在 SSA 中，每个定义获得唯一引用（`[1]`、`[2]`、`[3]`...），使用直接指向其定义。没有歧义。

### 为什么 SSA 重要

- **更简单的数据流分析**：每个值一个定义 → 用-定义链是平凡的
- **高效 CSE**：如果两条指令有相同的操作码和操作数，它们相同
- **死代码消除**：如果没人使用某定义，它就是死的
- **常量折叠**：如果所有操作数都是常量，结果就是常量

### 循环中的 φ 函数

SSA 在循环中有一个问题：如果变量在循环体中被修改，循环前的使用指向哪个定义？解决方案是 **φ（phi）函数**，它合并来自不同控制流路径的值。

LuaJIT 隐式处理 φ 函数。录制器在 `J->slot[]` 中追踪每个栈槽的当前值，当遇到循环回边时，知道哪个 IR 引用对应当前值。IR 中没有显式 φ 节点——录制器管理映射。

## IRIns 结构——64 位的瑞士军刀

LuaJIT IR 的基本单位是 `IRIns`——一个在不同编译阶段有不同用途的 64 位指令。

### 定义

```c
typedef union IRIns {
  struct { IRRef1 op1, op2; IROpT ot; IRRef1 prev; };
  struct { IRRef2 op12; IRType1 t; IROp1 o; uint8_t r; uint8_t s; };
  int32_t i; GCRef gcr; MRef ptr; TValue tv;
} IRIns;
```

同样的 64 位在不同上下文中有不同解释：

### 寄存器分配前

```
 ┌──────────┬──────────┬──────────┬──────────┐
 │  op1     │  op2     │   ot     │  prev    │
 │ (16 位)  │ (16 位)  │ (16 位)  │ (16 位)  │
 └──────────┴──────────┴──────────┴──────────┘
  操作数 1    操作数 2    类型+操作码   CSE 链
```

- `op1`、`op2`：操作数指令引用（各 16 位）
- `ot`：类型（8 位）+ 操作码（8 位）
- `prev`：链接此操作码的 CSE 跳表链

### 寄存器分配后

```
 ┌──────────┬──────────┬──────────┬──────────┐
 │  op1     │  op2     │   ot    │  r  │  s  │
 │ (16 位)  │ (16 位)  │ (16 位)  │寄存器│溢出 │
 └──────────┴──────────┴──────────┴──────────┘
  操作数 1    操作数 2    类型+操作码   寄存器/溢出
```

- `r`：分配给此指令结果的物理寄存器
- `s`：溢出槽（如果值被溢出到栈上）

`prev` 字段在分配后被**重新利用**。分配前，它链接 CSE 链。分配后，它保存寄存器/溢出信息。这是一个节省空间的技巧——优化完成后 CSE 链不再需要。

### 打包形式

```c
struct { IRRef2 op12; IRType1 t; IROp1 o; uint8_t r; uint8_t s; };
```

为快速访问，op1 和 op2 可以作为单个 32 位值（`op12`）读取。CSE 搜索使用这个：如果两条指令的 `op12` 和 `o` 匹配，它们就是相同的。

## 操作码集——约 120 个操作

LuaJIT 的 IR 有约 120 个操作码，按类别组织。每个操作码通过 `src/lj_ir.h` 中的 `IRDEF()` 宏定义。

### 守卫——推测执行的骨干

```
 LT    GE    LE    GT    EQ    NE    ABC    RETF
```

守卫是推测性断言。它们检查一个条件，要么继续，要么退出追踪。它们经过特殊对齐，使得相反条件可以通过 XOR 计算：`LT ^ 1 == GE`，`LT ^ 3 == GT`，`LT ^ 4 == ULT`。

```
 ┌─────────────────────────────────────────────────────────────┐
 │  守卫      │  检查                │  退出条件                 │
 ├───────────┼──────────────────────┼──────────────────────────┤
 │  LT       │  left < right        │  left >= right           │
 │  GE       │  left >= right       │  left < right            │
 │  EQ       │  left == right       │  left != right           │
 │  ABC      │  数组边界检查         │  索引越界                │
 │  RETF     │  从帧返回            │  帧不匹配                │
 └─────────────────────────────────────────────────────────────┘
```

### 常量——驻留值

```
 KPRI   KINT   KGC   KPTR   KKPTR   KNULL   KNUM   KINT64   KSLOT
```

常量被**驻留**——相同常量共享同一个 IR 引用。这使得常量 CSE 成为可能：如果两条指令加载相同常量，它们共享同一个引用。

### 算术

```
 ADD   SUB   MUL   DIV   MOD   POW   NEG   ABS   MIN   MAX   FPMATH
 ADDOV SUBOV MULOV   （溢出检查变体）
```

溢出检查变体（`ADDOV`、`SUBOV`、`MULOV`）在整数溢出时设置溢出标志。优化器可以在证明溢出不可能时剥离这些检查（窄化）。

### 内存操作

```
 引用:   AREF   HREF   NEWREF   UREFO   UREFC   FREF   STRREF   LREF
 加载:   ALOAD  HLOAD  ULOAD    FLOAD   XLOAD   SLOAD  VLOAD
 存储:   ASTORE HSTORE USTORE   FSTORE  XSTORE
```

`IRDELTA_L2S` 常量将每个加载操作码映射到对应的存储操作码。FWD 阶段用它来匹配加载与其前面的存储。

### 分配

```
 SNEW   XSNEW   TNEW   TDUP   CNEW   CNEWI
```

这些分配新对象。它们流入 SINK 阶段，尽可能将分配到退出路径延迟。

### 屏障

```
 TBAR   OBAR   XBAR
```

GC 写屏障。`TBAR` 用于表存储，`OBAR` 用于对象存储，`XBAR` 用于跨页存储。这些确保三色 GC 不变量被维持。

### 转换

```
 CONV   TOBIT   TOSTR   STRTO
```

类型转换。`CONV` 是通用转换，模式编码在 `op2` 中（源类型、目标类型、截断模式）。

### 调用

```
 CALLN   CALLA   CALLL   CALLS   CALLXS   CARG
```

- `CALLN`：普通 C 函数调用
- `CALLA`：带参数调整的调用
- `CALLL`：尾调用
- `CALLS`：慢调用（带钩子检查）
- `CALLXS`：跨状态调用
- `CARG`：调用参数

## 类型系统——从位到语义

每条 IR 指令携带一个 8 位类型字段，驱动优化和代码生成。

### 类型类别

```
 ┌─────────────────────────────────────────────────────────────┐
 │  类型          │  含义                                       │
 ├───────────────┼─────────────────────────────────────────────┤
 │  IRT_NIL      │  空值                                       │
 │  IRT_TRUE/FALSE │  布尔值                                   │
 │  IRT_LIGHTUD  │  轻量用户数据（32 位指针）                  │
 │  IRT_STR      │  字符串指针                                 │
 │  IRT_P32      │  32 位指针                                  │
 │  IRT_P64      │  64 位指针                                  │
 │  IRT_INT      │  整数值                                     │
 │  IRT_NUM      │  双精度值                                   │
 │  IRT_I8/U8    │  8 位整数                                   │
 │  IRT_I16/U16  │  16 位整数                                  │
 │  IRT_U32      │  32 位无符号整数                            │
 │  IRT_I64/U64  │  64 位整数                                  │
 │  IRT_FLOAT    │  32 位浮点                                  │
 │  IRT_SOFTFP   │  软件浮点（拆分为 2x int32）               │
 └─────────────────────────────────────────────────────────────┘
```

### 类型标志

- `IRT_GUARD`：此指令是守卫。其结果类型是正在检查的类型。
- `IRT_ISPHI`：此指令代表 φ 合并点。
- `IRT_MARK`：优化期间的临时标记。

### 模式表

`lj_ir_mode[]` 数组编码每个操作数的约束：

```c
enum {
 IRMnone,   // 无操作数
 IRMref,    // IR 引用
 IRMlit,    // 字面量值
 IRMckst,   // 常量引用
  // 标志:
 IRM_Comm   // 可交换
 IRM_A      // 分配
 IRM_L      // 加载
 IRM_S      // 存储
 IRM_W      // 非弱守卫
};
```

此表驱动 FOLD 引擎：它知道哪些操作数可以是常量，哪些操作可交换，哪些有副作用。

## 引用系统——常量与指令

LuaJIT 的 IR 使用一个巧妙的引用编号方案，让常量和指令共享同一个引用空间。

### REF_BIAS——支点

```
 ┌─────────────────────────────────────────────────────────────┐
 │                    引用空间                                  │
 │                                                             │
 │  0x0000  ← 常量这样增长（向下）                              │
 │    ...                                                      │
 │  REF_BIAS - 2   ← 最后一个常量                               │
 │  REF_BIAS - 1   ← 第一个常量                                 │
 │  REF_BIAS       ← 支点（IR 引用的"零"）                      │
 │  REF_BIAS + 1   ← 第一条指令                                 │
 │  REF_BIAS + 2   ← 第二条指令                                 │
 │    ...                                                      │
 │  0xFFFF   ← 指令这样增长（向上）                             │
 └─────────────────────────────────────────────────────────────┘
```

- 常量：`REF_BIAS - idx`（从 REF_BIAS 向下增长）
- 指令：`REF_BIAS + idx`（从 REF_BIAS 向上增长）

这意味着常量和指令永远不会冲突——它们从支点向彼此增长。

### 常量驻留

当录制器创建常量时，首先检查相同常量是否已存在。如果存在，则重用引用。这通过哈希表（`J->khash`）实现：

```c
// 简化的常量驻留
IRRef lj_ir_kint(jit_State *J, int32_t k) {
  // 检查此整型常量是否已存在
  IRRef ref = find_khash(J, IRT_INT, k);
  if (ref) return ref;  // 重用已存在的常量
  // 创建新常量
  return new_kint(J, k);
}
```

驻留使常量 CSE 成为可能：如果两条指令加载相同整数，它们共享同一个引用，FOLD 引擎将它们识别为相同。

## 录制器如何发射 IR

追踪录制器（`lj_record_ins()`）将字节码翻译为 IR。对于每条字节码指令，它：

1. 从 `J->slot[]` 读取当前栈槽
2. 通过 `emitir()` 宏发射 IR
3. 用结果引用更新槽映射

### emitir 宏

```c
#define emitir(ot, a, b)  (lj_ir_set(J, (ot), (a), (b)), lj_opt_fold(J))
```

这做两件事：
1. `lj_ir_set()`：用给定类型和操作数创建新的 IR 指令
2. `lj_opt_fold()`：立即对新指令运行 FOLD 引擎

即时折叠是关键——常量在创建时就被折叠，代数化简在录制期间发生，而非之后。

### 类型特化的实际效果

```lua
-- Lua 源码
local x = 0
for i = 1, 100 do
  x = x + i
end
```

录制的 IR（简化）：

```
 [1] KINT 0           ; x = 0（初始值）
 [2] KINT 1           ; i = 1（循环起始）
 [3] KINT 100         ; 循环上限
 [4] ISNUM [2]        ; 守卫：i 是数字
 [5] ISNUM [1]        ; 守卫：x 是数字
 [6] ADD [1], [2]     ; x + i（已知都是数字）
 [7] ADD [2], KINT 1  ; i + 1
 [8] LE [7], [3]      ; i <= 100?
 [9] PHI [6], [5]     ; x = (x+i) 或 0（循环合并）
 [10] PHI [7], [2]    ; i = (i+1) 或 1（循环合并）
```

[4] 和 [5] 处的守卫特化了类型。之后，[6] 处的 ADD 知道两个操作数都是数字，可以使用单条 `addsd` 指令。

## 优化流水线——变换 IR

录制完成后，IR 经过一系列优化阶段。每个阶段原地变换 IR。

### 流水线

```
                    ┌──────────────────────────────────────────┐
                    │           录制的 IR                       │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  FOLD（录制期间）                          │
                    │  常量折叠、代数化简                        │
                    │  ABC 消除、CSE                             │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  DCE（LOOP 之前）                         │
                    │  死代码消除                                │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  LOOP                                     │
                    │  循环不变量外提                            │
                    │  复制替换展开                              │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  NARROW                                   │
                    │  双精度 → int32 窄化                      │
                    │  溢出检查剥离                              │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  FWD + DSE                                │
                    │  加载前递（L2L、S2L）                      │
                    │  死存储消除                                │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  SPLIT（仅软件浮点）                       │
                    │  64 位 → 32 位拆分                        │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │  SINK                                     │
                    │  分配下沉                                  │
                    │  延迟存储到退出路径                        │
                    └──────────────────┬───────────────────────┘
                                       │
                    ┌──────────────────▼───────────────────────┐
                    │          优化后的 IR                       │
                    └──────────────────────────────────────────┘
```

### FOLD——优化的核心

FOLD 引擎在每条发射的指令上运行。它使用**半完美哈希表**进行模式匹配：

1. 从 `(ins_opcode, left_opcode, right_opcode)` 构建 24 位键
2. 在生成的 `fold_hash[]` 表中查找键
3. 如果不匹配，用通配符掩码重试：`ins left right` → `ins any right` → `ins left any` → `ins any any`
4. 执行折叠函数（常量折叠、化简、CSE 等）

这是一种**编译时元编程**技术：源码中的 `LJFOLD` 宏由 Lua 脚本解析，生成最优查找表。

### NARROW——预测性窄化

NARROW 阶段保持数字为双精度，仅在有益时窄化为 int32：
- **归纳变量**：可证明为整数的循环计数器
- **索引表达式**：适合 int32 的数组索引
- **溢出剥离**：当输入已是整数时 `ADDOV → ADD`

它使用**反向传播缓存**（`BPropEntry bpropcache[BPROP_SLOTS]`）将窄化需求反向传播通过 IR。

### LOOP——通过复制替换优化循环

不同于传统 LICM（因守卫控制依赖在动态语言中失败），LuaJIT 使用**复制替换展开**：

1. 发射 `LOOP` 指令分隔预卷和循环体
2. 用替换的操作数重新发射所有已录制的指令
3. 预卷为自身和循环体都维护控制依赖
4. φ 消除：在替换期间收集潜在 φ，消除冗余的

如果循环优化失败（类型不稳定、守卫失败），它撤销更改并**继续录制**——一种独特的「通过录制展开循环」恢复机制。

## 从 IR 到机器码——发射器

最后阶段将优化后的 IR 转换为机器码。

### 汇编过程

```c
void lj_asm_trace(jit_State *J, GCtrace *T) {
  // 预留 MCode 区域（RW）
  MCode *mcarea = lj_mcode_reserve(J, &lim);

  // 逆序处理指令（从最后到第一条）
  for (as->curins--; as->curins > as->stopins; as->curins--) {
    IRIns *ir = IR(as->curins);
    if (!ra_used(ir) && !ir_sideeff(ir)) continue;  // DCE
    if (irt_isguard(ir->t)) asm_snap_prep(as);      // 准备快照
    asm_ir(as, ir);                                  // 发射指令
  }

  // 发射头部（追踪入口）和尾部（退出桩）
  // 提交 MCode（RW → RX）
  lj_mcode_commit(J, mctop);
}
```

### 关键要点

- **逆向汇编**：指令从后往前处理。这使得寄存器分配器能知道每个点的活跃寄存器。
- **线性扫描分配**：寄存器按提示分配（如 `CALL*` 结果 → `RID_RET`，x86 移位计数 → `RID_ECX`）。
- **退出桩**：每个守卫有一个退出桩，保存状态并跳转到 `lj_vm_exit_handler`。
- **快照准备**：在发射守卫前，发射器记录哪些 IR 引用映射到哪些栈槽（用于去优化）。

### IR → x86-64 映射示例

```
 IR:                              x86-64:
 [1] KINT 42                      mov eax, 42
 [2] ADD [1], KINT 1              add eax, 1
 [3] ISNUM [2]                    test eax, 0x7ff00000
                                  jnz .exit_guard_1
 [4] MUL [2], KINT 2              lea eax, [rax+rax]  ; 强度削减
 [5] RET                          ret
```

发射器应用自己的优化：强度削减（`MUL(x,2)` → `LEA(x+x)`）、寄存器合并、内存操作数融合。

## 常见问题解答

### 为什么用 SSA？

SSA 简化编译器分析。单一定义点使用-定义链易于计算，CSE 是简单的哈希查找，死代码消除很直接。代价——控制流合并的 φ 函数——由 LuaJIT 的录制器隐式处理。

### LuaJIT 如何处理 φ 函数？

隐式地。录制器在 `J->slot[]` 中追踪每个栈槽的当前 IR 引用。遇到循环回边时，知道哪个引用对应当前值。IR 中没有显式 φ 节点——映射由录制器管理。

### 能在运行时检查 IR 吗？

可以。用 `-jdump` 标志运行 LuaJIT：`luajit -jdump=bitmsx your_script.lua`。这会为每个编译的追踪转储 IR，显示操作码、类型和快照。这是理解 JIT 在做什么的宝贵工具。

### 为什么常量被驻留？

去重。如果两条指令加载相同常量，它们共享同一个 IR 引用。这使得常量 CSE（相同指令被合并）成为可能，并减少追踪大小。每次常量创建的哈希表查找是 O(1)。

### ADD 和 ADDOV 有什么区别？

`ADD` 是普通整数加法（溢出时回绕）。`ADDOV` 检查整数溢出并在溢出时退出追踪。NARROW 阶段可以在证明输入足够小不可能溢出时剥离溢出检查（`ADDOV → ADD`）。
