# SVG 渲染问题排查与修复指南

本文档总结了博客图表 SVG 在渲染和转换过程中遇到的问题、排查方法和修复经验。

## 问题发现

### 症状

在将 SVG 图表转换为 PNG 验证效果时，发现饼图（donut chart）存在以下视觉问题：
- 黄色扇形区域溢出圆形边界
- 圆形形状不协调，各扇形连接处不光滑
- 整体视觉效果不符合预期

### 根本原因

SVG 中 `<path>` 元素的弧线（Arc）坐标计算错误。具体来说：
- 弧线端点坐标不在正确的圆周上
- 点到圆心的距离不等于声明的半径

**验证方法：** 计算点到圆心的距离是否等于半径。

例如，原始 SVG 中 Property 扇形的终点为 `(324.8, 247.6)`，圆心 `(210, 175)`，声明半径 `130`：
```
距离 = √((324.8-210)² + (247.6-175)²) = √(13179 + 5271) = √18450 ≈ 135.8 ≠ 130
```
距离 135.8 ≠ 半径 130，证明该点不在圆周上。

## SVG 饼图/环形图坐标计算

### 参数定义

| 参数 | 含义 | 示例值 |
|------|------|--------|
| `cx, cy` | 圆心坐标 | 210, 175 |
| `r_outer` | 外半径 | 130 |
| `r_inner` | 内半径（环形图） | 80 |
| `angle_from_top` | 从顶部（12点方向）顺时针测量的角度 | 0° - 360° |

### 坐标计算公式

对于从顶部顺时针测量的角度 `θ`（单位为度）：
```
x = cx + r × sin(θ × π/180)
y = cy - r × cos(θ × π/180)
```

### 路径结构

每个扇形由 4 个点组成，路径格式为：
```
M x1 y1          // 外弧起点
A r r 0 0 1 x2 y2  // 外弧终点（顺时针）
L x3 y3          // 连接到内弧终点
A r r 0 0 0 x4 y4  // 内弧起点（逆时针）
Z                // 闭合
```

其中 `A` 命令的参数为：`A rx ry x-axis-rotation large-arc-flag sweep-flag x y`
- `large-arc-flag`: 0 = 弧线 ≤ 180°，1 = 弧线 > 180°
- `sweep-flag`: 0 = 逆时针，1 = 顺时针

### 计算示例

以 Property 扇形（35%，0° 到 126°）为例：

```
外弧起点 (θ=0°):
  x = 210 + 130 × sin(0°) = 210
  y = 175 - 130 × cos(0°) = 45

外弧终点 (θ=126°):
  x = 210 + 130 × sin(126°) = 210 + 105.17 = 315.17
  y = 175 - 130 × cos(126°) = 175 + 76.42 = 251.42

内弧终点 (θ=126°):
  x = 210 + 80 × sin(126°) = 210 + 64.72 = 274.72
  y = 175 - 80 × cos(126°) = 175 + 47.01 = 222.01

内弧起点 (θ=0°):
  x = 210 + 80 × sin(0°) = 210
  y = 175 - 80 × cos(0°) = 95
```

完整路径：
```
M 210 45 A 130 130 0 0 1 315.17 251.42 L 274.72 222.01 A 80 80 0 0 0 210 95 Z
```

## 常见错误

### 1. 角度方向混淆

- **错误：** 使用标准数学角度（从正 X 轴逆时针测量）
- **正确：** 饼图通常从顶部（12 点方向）顺时针测量

### 2. Y 轴方向忽略

- **错误：** 使用 `y = cy + r × cos(θ)`（标准数学坐标系）
- **正确：** 使用 `y = cy - r × cos(θ)`（SVG 坐标系 Y 轴向下）

### 3. 半径不一致

- **错误：** 弧线端点到圆心的距离不等于声明半径
- **正确：** 每个端点必须精确落在对应半径的圆周上

### 4. 弧线标志错误

- **错误：** `large-arc-flag` 或 `sweep-flag` 设置错误
- **正确：** 根据弧线实际角度和方向设置标志

## 验证方法

### 方法 1：距离验证

对每个端点，计算其到圆心的距离：
```python
import re, math

def verify_svg_arcs(svg_path, cx, cy, expected_radius):
    # 提取所有坐标点
    points = re.findall(r'[ML]\s*([\d.]+)\s+([\d.]+)', svg_path)
    for x, y in points:
        x, y = float(x), float(y)
        dist = math.sqrt((x-cx)**2 + (y-cy)**2)
        if abs(dist - expected_radius) > 0.5:
            print(f"ERROR: ({x},{y}) distance={dist:.2f} != radius={expected_radius}")
```

### 方法 2：可视化验证

将 SVG 转换为 PNG 后直接查看效果：
```bash
# 使用 rsvg-convert（推荐，最准确）
rsvg-convert -w 1200 input.svg -o output.png

# 或使用 Chromium 截图
# （需要启动 Chromium 并使用 puppeteer 截图）
```

### 方法 3：浏览器预览

在浏览器中直接打开 SVG 文件，检查：
- 各扇形是否对齐
- 是否有溢出或间隙
- 圆心位置是否正确

## 转换工具对比

| 工具 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| `rsvg-convert` | 渲染准确、速度快、命令行工具 | 需要安装 librsvg | 批量转换、自动化 |
| Chromium + puppeteer | 与浏览器渲染一致 | 启动慢、需要 Node.js | 需要精确浏览器渲染 |
| sharp (Node.js) | 纯 JS、API 简洁 | 需要 Node.js 20+、arm64 兼容问题 | Node.js 项目内转换 |
| ImageMagick | 功能全面 | 渲染质量不如 rsvg、需要安装 | 简单转换 |

```bash
# Ubuntu/Debian
sudo apt install librsvg2-bin

# 验证安装
rsvg-convert --version
```

## 经验教训

### 1. 生成 SVG 时验证坐标

不要仅凭视觉检查 SVG 图表。生成后应：
- 用脚本验证所有端点到圆心的距离
- 转换为 PNG 后读取并检查
- 在浏览器中打开确认

### 2. 使用正确的坐标系统

SVG 使用 Y 轴向下的坐标系，与标准数学坐标系不同。计算坐标时必须：
- X 坐标：`cx + r × sin(θ)`
- Y 坐标：`cy - r × cos(θ)`（注意负号）

### 3. 角度从顶部开始

饼图/环形图通常从 12 点方向（顶部）开始，顺时针测量角度。这与标准数学的 3 点方向（右侧）逆时针不同。

### 4. 弧线标志要正确

- `large-arc-flag`: 弧线角度 ≤ 180° 时为 0，> 180° 时为 1
- `sweep-flag`: 顺时针为 1，逆时针为 0

### 5. 转换前检查 SVG 有效性

使用 `xmllint --noout` 验证 SVG 是有效的 XML，但不会验证几何正确性。几何正确性需要额外的验证步骤。

### 6. 字体问题

SVG 中的文字可能因系统缺少字体而显示为方块（□□□）。解决方案：
- 安装所需字体（如 `fonts-noto-cjk` 用于中文）
- 或将文字转换为路径（`<path>`）

## 修复清单

修复 SVG 图表时，按以下顺序检查：

- [ ] `xmllint --noout` 验证 XML 有效性
- [ ] 检查 `xmlns="http://www.w3.org/2000/svg"` 存在
- [ ] 检查所有 `&` 已转义为 `&amp;`
- [ ] 验证所有端点到圆心的距离 = 声明半径
- [ ] 检查弧线标志（large-arc-flag, sweep-flag）正确
- [ ] 转换为 PNG 后读取并检查视觉效果
- [ ] 检查文字是否正常显示（无方块）
- [ ] 在浏览器中打开 SVG 确认渲染正确
